# 배포 서비스 (Forge형 BYOC) — 비즈니스 모델 & 컨트롤 플레인 설계

> OSS 푸시 서버(도커)를 **고객의 서버에 원클릭으로 이식·관리**하는 SaaS.
> 제품 문서는 `README.md`, 이 문서는 그 위의 **상용 레이어**.
>
> 작성일: 2026-09-04 · 상태: 구상(OSS 트랙션 후 착수)

---

## 1. 개요 — "푸시용 Forge"
- **모델:** BYOC(Bring Your Own Cloud) / 오픈코어 + 컨트롤 플레인
- **OSS 서버(docker-compose)** = 배포되는 산출물
- **컨트롤 플레인(당신의 SaaS)** = 고객 서버에 그걸 **설치·업데이트·모니터링**
- 고객은 **자기 서버/클라우드 요금만** 부담(데이터 주권), 당신은 **관리 구독료** 수취

**비교:** Laravel Forge / Ploi / RunCloud(정확히 이 모델), Coolify(OSS PaaS, 참고/기반), Kamal(도커 배포 도구, 래핑 대상).

---

## 2. 제품 관계 (깔때기)
```
OSS 발견 → DIY 셀프호스트(무료, 무제한)
   ↓ 관리 귀찮음
관리형 무료 1대(원클릭 배포/업데이트/모니터링)
   ↓ 서버 늘리거나 팀/고급기능 필요
Pro 유료(서버당) → Enterprise(SSO/SLA)
```
- **OSS 서버 = 무료 유입 깔때기**, **컨트롤 플레인 = 주 수익.**
- 파는 것은 서버가 아니라 **"관리 편의"**.

---

## 3. 컨트롤 플레인 아키텍처

### 3-1. 연결 방식
| 방식 | 작동 | 장단점 |
|---|---|---|
| A. SSH(Forge식) | 고객 SSH 정보 → 컨트롤플레인이 접속 배포 | 단순, 근데 SSH키 보관 부담·인바운드 이슈 |
| **B. 에이전트(권장)** | 고객 서버에 경량 에이전트 설치 → **아웃바운드**로 접속, 명령 수신·헬스/로그 보고 | 인바운드 불필요, 보안↑, 다수 서버 용이 |

> **권장 B** — `curl \| sh` 한 줄로 에이전트 설치 → 이후 클릭으로 배포/업데이트/롤백.

### 3-2. 컨트롤 플레인이 하는 일
1. **연결**: 서버 등록(에이전트) 또는 클라우드 API키로 **신규 프로비저닝**(Hetzner/DO/AWS)
2. **배포**: docker-compose 푸시, env 주입, 마이그레이션, **TLS 자동**(Caddy/Traefik + Let's Encrypt)
3. **운영**: 버전 롤아웃/롤백(카나리·헬스게이트), 헬스·메트릭·로그 스트리밍, 백업 스케줄, 알림
4. **멀티서버 대시보드**: 고객별 여러 서버/프로젝트 관리

### 3-3. 스택
- 컨트롤 플레인: **Next.js**(대시보드) + BullMQ + Postgres + **Stripe**(결제)
- 배포 엔진: **Kamal 래핑** 또는 Ansible/SSH, 신규서버는 **Terraform**
- 에이전트: 경량 Go/Node 바이너리(아웃바운드 웹소켓 + 도커 제어)

> 도커-퍼스트 + [컨트롤-플레인 친화 5원칙](README.md#5-6--컨트롤-플레인-친화-5원칙-지금부터-지킬-것)을 지킨 덕에 배포 엔진이 "docker-compose 얹기"로 단순화됨.

## 4. 요금제

### 4-1. 경로 구분 (중요)
| 경로 | 과금 | 이유 |
|---|---|---|
| **DIY 셀프호스트**(컨트롤플레인 없이 직접) | **항상 무료·무제한** | OSS 신뢰·유입. 막을 수도, 막아서도 안 됨 |
| **관리형(컨트롤플레인 경유)** | **1대 무료 → 2대째 유료** | "관리 편의"를 파는 것 |

### 4-2. 티어
| | Free | Pro | Enterprise |
|---|---|---|---|
| 관리 서버 수 | **1대** | 2대~(**서버당 과금**) | 무제한/전용 |
| 프로젝트·앱 | 무제한 | 무제한 | 무제한 |
| 푸시 전송량 | 무제한(고객 FCM=무료) | 무제한 | 무제한 |
| 핵심(전송/토픽/템플릿/대시보드) | ✅ | ✅ | ✅ |
| 팀 seat | 1~2 | 다수 | 무제한+RBAC |
| 고급(세그먼트·A/B·웹훅·긴 리텐션·자동백업) | 제한 | ✅ | ✅ |
| SSO/SAML·감사로그·SLA | ✖ | 일부 | ✅ |
| 지원 | 커뮤니티 | 우선 | 전담 |

**가격 감:** Forge ~$12–19/서버, Coolify ~$5–10 → **서버당 월 $10~15**에서 시작.

### 4-3. Free 1대 한도 (남용 방지·지속가능)
- 서버 1대 + 프로젝트 무제한, **단** 로그 리텐션 짧게(7일), 자동백업/SSO/우선지원 제외 → 자연 업그레이드 유인
- 전송량 무제한 OK(고객이 자기 FCM·자기 서버로 발송 = **당신 비용 아님**)

## 5. 과금 집행
- 컨트롤 플레인이 **계정별 연결 서버 수 미터링**
- **Stripe** 구독, 서버 #2 등록 시 **결제 게이트**
- ⚠️ **무료 1대는 인질 금지** — 결제 실패해도 기존 1대 유지(신뢰·평판)
- **오픈코어 경계**: 서버 코드=전부 무료 OSS / 유료=컨트롤플레인 **다중서버·고급기능·지원**

---

## 6. 경제성
고객이 **자기 서버·자기 FCM** 사용 → 무료 1대의 **한계비용 ≈ 컨트롤플레인 오케스트레이션분(작음)**. 인프라 비용을 고객이 부담하므로 프리미엄이 지속 가능.

## 8. 리스크 & 완화
| 리스크 | 완화 |
|---|---|
| 이기종 환경 | Forge처럼 **"Ubuntu + Docker"로 지원 범위 제한** |
| 고객 서버 접근 보안 | 에이전트(아웃바운드) + 최소권한 + 키 볼트 |
| 다수 서버 업데이트 신뢰성 | 카나리·롤백·헬스게이트 |
| 지원 부담 | 표준화 환경 + 자동 진단 |
| OSS 포크로 무료화 우려 | 유료는 "편의·지원"이라 포크해도 관리부담이 그들 몫 |

## 9. 로드맵 (OSS 트랙션 후 착수)
1. **선행 조건**: OSS 서버가 도커로 잘 돌고, 셀프호스트 채택 지표가 나옴
2. **PoC**: 에이전트 + 클라우드 1곳(Hetzner/DO) + Kamal로 "원클릭 배포" 데모
3. **MVP**: 서버 등록·배포·업데이트·롤백·헬스, 무료 1대 + Stripe 결제(2대째)
4. **v1**: 멀티서버 대시보드, 백업, 알림, 로그 스트리밍
5. **확장**: 멀티클라우드 프로비저닝, 팀/RBAC, SSO/SLA(Enterprise)

---

## 10. 결론
- **좋은 확장.** OSS(무료 유입) → BYOC 관리형(주 수익) → 완전관리(편의) 깔때기 완성.
- **차별화**: "셀프호스트 멀티테넌트 푸시" + "고객 서버 원클릭 배포" = OSS 경쟁군에 없는 조합.
- **순서**: OSS 서버 먼저(도커-퍼스트), 컨트롤 플레인은 검증 후.
